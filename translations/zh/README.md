# 保留记录。更换型号。

![一个人的记录保留在一处，而单独的工作部分处理有限的工作。](../../illustrations/specialist-assembly-line-vs-giant-chatbot.png)

Robot Brain 是用于保存长期运行的人类工作背后的历史和意义的软件。它不是语言模型、聊天机器人或将每个问题转发给模型的服务。

大型语言模型可以研究、编写、解释并帮助解决难题。围绕它们构建的付费服务仍然是临时工作空间。他们可以缩短冗长的对话，丢失先前的指示，将结论与证据分开，并继续写作，就好像缺失的历史仍然存在一样。然后，一个人会花费更多的时间和付费使用来重建已经提供的上下文。

该软件改变了持久价值所在。该人的对话、文件、决定、失败的尝试、更正和未解答的问题都保留在该人控制的记录中。本地程序可以检查这些记录。语言模型可以帮助完成选定的工作，但其贡献会作为过时的、可审查的工作返回到记录中。然后可以替换该模型，而无需保留历史记录。

## 一种观点的差异

| 商业语言模型服务 | Robot Brain |
|---|---|
| 从当前工作视图中的材料生成答案。 | 保留完整的来源及其周围的历史。 |
| 随着工作的增长，可能会缩短或失去之前的谈话。 | 保存每个模型外部的对话，以便可以再次使用。 |
| 融合了从许多来源学到的知识，但没有完整的路径返回到每个来源及其环境。 | 将每个已知来源、后来的发现、更正和分歧保留为单独的记录。 |
| 可以在一次交流中编写、搜索、计划和判断自己的答案。 | 对具有有限权限的单独部分进行保存、搜索、分析、编写、检查和批准。 |
| 控制模型、服务规则、​​使用限制和产品变更。 | 将持久记录置于该人的控制之下。 |
| 因失败的尝试、纠正性交流以及有用的工作而获得报酬。 | 保留失败和更正，这样他们的课程就不必再次购买。 |

Robot Brain 可以调用本地或在线语言模型。这不会将其变成模型代理。它可以保存、搜索、比较、组织和重建早期工作，而无需调用参与原始对话的模型。当模型有用时，请求是独立于该模型而存在的更大流程中的一个步骤。

## 为什么要建造这个

开发过程中可用的最强大的付费通用模型是有能力但不可靠的长期工作托管人。

记录的故障包括丢失指令、丢失证据、虚构连接、过早声明完成、不需要的更改以及工作文件损坏。纠正这些失败需要更多的请求、更多的测试、更多的津贴以及更多的人的时间和精力。这些服务不会自动返还无法使用的工作所花费的使用量或修复它所需的交换。

这个问题比任何一个糟糕的答案都要严重。一个临时的文本生成器被要求充当记忆、历史学家、研究员、作家、检查员和最终法官。改变模型并没有改变这种安排。

Robot Brain 围绕不同的安排构建：首先保留人类记录，让几个可替换的部件对其做出贡献，并在接受重要工作之前需要生成模型之外的证据。

## 经过训练的模型无法保留什么

大型语言模型从大量人类工作中学习模式。这些模式使模型变得有用，但模型并不是塑造它的完整作品的库。

在模型内部，来自书籍、文章、对话、翻译、社区、标签和人类反馈的影响混合在一起。该模型通常无法显示哪些来源塑造了特定的句子。它无法恢复每个作者的目的、受众、证据、分歧、后来的更正或缺失的观点。

即使原作仍然存在于其他地方，这也是一种意义的丧失。该模型保留了工作中的一些有用性，同时放弃了返回其人类环境的可靠路径。

平时使用时也会出现同样的问题。在赋予其意义的对话被缩短后，最终的答案可能会保留下来。结论仍然存在，但失败的尝试、不确定性及其背后的原因从模型的工作视图中消失了。

这个项目并没有通过训练另一个关于人的生活的模型来解决这个问题。个人历史仍然是可读和可追溯的，而不是被混合到另一个经过训练的模型中。模型使用选定的记录；它们不会成为记录。

## 每个部分的作用是什么

工作软件将聊天服务通常使之看起来像是一项活动的工作分开：

一. **源管理员保存发生的事情。**它保留对话、文档、图像或其他材料，而不用摘要替换它。
二. **可搜索的副本使源更容易找到。**复制的文本、描述和索引指向未更改的源并且可以重建。
三. **专注的本地读者检查特定特征。**单独的方法着眼于语言、陈述、关系、推理、时间、人类经验和价值观。每个人只报告自己的发现及其背后的段落。
四. **历史记录使变化可见。** 添加新的发现、更正、分歧、失败的尝试和未解决的问题，而无需重写先前的事件。
五. **请求构建器收集一项工作所需的内容。**它选择相关来源和调查结果，并记录包含或遗漏的内容。
六. **语言模型可能会提供有限的帮助。**本地模型可以提供广泛的背景。在线模型可以帮助进行困难的研究或写作。任何一个回复都仍然是有日期的贡献，可以检查、拒绝或替换。
七. **单独检查将结果与请求和证据进行比较。** 编写答案的模型不能声明自己的工作已被接受。
八. **一个屏幕可以让人们使用该软件。**LibreChatfork 就是这样的屏幕之一。更换它并不会更换记录或其他工作部件。

没有任何一个部分被呈现为无所不知的助手。他们的工作有限，因此每个部件都可以更换。

## 让已完成的对话再次发挥作用

完整的对话包含人的请求、语言模型的实际答复、尝试的工作、失败、更正以及交换结束的点。这些消息保留了原始模型贡献的内容，而不需要该模型稍后进行自我解释。

专注的本地读者从多个角度审视保存下来的交流。他们可以在不依赖广泛的世界知识的情况下找到详细的模式和关系。他们各自的发现仍然与谈话的具体部分有关。

这些发现在形成清晰的解释之前可能仍然需要普通的背景知识。对于这个有限的步骤，一个小的Qwen模型在本地运行vLLM。它添加了一个过时的概述，有助于连接详细的调查结果并解释交换所取得的成果。

Qwen无法恢复在线模型的隐藏想法或训练历史。它提供了广泛的背景知识，这些知识并非原始模型所独有。原始模型的有用贡献已经保留在它生成的单词中。

这Qwen概述存储在来源和早期发现旁边。可以对其进行修正或更换。原始对话和详细的本地分析保持不变。

## 现在正在做什么

当前的实现可以保留完整的对话，通过单独的本地方法对其进行检查，添加本地一般知识阅读，并将每个保留的贡献收集到可以稍后重建的记录中。

当外部帮助有用时，它还可以准备有限的在线模型请求。该服务仅接收选定的材料。它的答案返回到本地记录，其中检查和人工批准（而不是模型）决定保留什么。

这是核心成就：曾经依赖于一次临时对话的工作在聊天屏幕、模型和提供程序消失后仍然有用。
