# 付费语言模型服务中观察到的失败及其导致的保障措施

![记录下来的故障成为以后工作的检验和保障。](../../illustrations/failures-became-blueprint.png)

## 这些是可用的最强付费选项

该项目使用付费在线语言模型服务进行研究、编码、写作和审阅。这些帐户包括当时这些服务提供的最强大的通用模型。选择功能更强大的付费选项并不能避免以下失败。

每个示例都来自带有日期的项目记录。这些表格描述了付费模型做了什么、接下来发生了什么以及在模型之外构建了哪些保护措施。这些是在商业服务中观察到的故障，而不是由Robot Brain。右栏描述了该项目的反应。

这些记录不会猜测提供商的动机或声称了解未公开的技术原因。提供商名称被省略，因为保护措施针对的是重复行为而不是一家公司。

## 失败的代价是什么

代价不仅限于错误答案。

- **时间被浪费了。** 描述为已完成的工作必须由人员进行检查、再次解释、修理和测试。有些失败会耗费数小时。
- **付费使用津贴（有时称为配额）丢失了。**重试、重复上下文、替换草稿和更正使用与有用工作相同的有限津贴。在这些记录的会话中，不会为不可用的输出或纠正交换返回自动配额。
- **无论哪种方式，服务都是付费的。** 订阅或使用费用仍然存在，同时该人还花费了查找和修复故障所需的时间和精力。
- **工作被破坏。**不完整的编辑导致实时服务无法运行。对错误的设置副本进行了更改。输出被移离其所需位置，而不是修复访问。
- **历史记录面临风险。**生成的文本与人类材料混合，并且在该人批准更改之前更改或删除了记录。
- **未经许可就消耗了注意力。**重要的答案被隐藏在重复的解释中，迫使人们阅读所有内容以恢复重要的一小部分。

这就是为什么重要的规则不仅仅存在于此处的提示中。Robot Brain 检查实际发生的情况，即使模型表明贡献成功，也可以拒绝贡献。

## 连续性和知识失败

| 观察到的故障 | 发生了什么 | 在语言模型之外添加的保护 |
|---|---|---|
| 失去历史后听起来连续 | 一项服务缩短了之前的对话以适应其工作限制。它保留了一些结论，但丢失了来源、更正、拒绝的替代方案、事件顺序和用户意图，同时听起来仍然很流畅。 | 保持整个对话的秩序。单独保存缩短的版本并记录其中包含、省略和可能丢失的内容。 |
| 一个新的答案取代了记录的历史 | 更新的语言模型答案可能会取代之前的一切，尽管它来自关于世界的不同信息、规则和选择。 | 保存每个发现的时间。永远不要让最新的答案覆盖之前接受、拒绝或不确定的发现。 |
| 语言模型学习破坏了回归源头的路径 | 语言模型保留了有用的模式，同时将它们与源的创建者、目的、受众、证据、分歧和后来的历史分开。 | 在每种语言模型之外保持源代码及其已知联系不变。将不受支持的语言模型知识视为建议，除非单独的证据将其重新连接到来源。 |
| 失去语言模型学习背后的环境 | 语言模型仍然有用，但它的答案无法揭示塑造它的所有人员、来源、目的、分歧、许可和文化。 | 保留已知的情况并保留语言模型之外保存的来源的信用。将不受支持的学习知识视为语言模型建议，而不是与来源相关的事实。 |
| 所选内容存在隐藏偏见 | 语言模型可以识别的内容反映了用于构建它的语言、来源、档案、标签、人工审阅者和目标。它的答案并没有揭示所有这些影响。 | 记录语言模型的已知限制以及对其学习的材料的了解。比较几种有限的工具，不要将一个顺利的答案视为一个完整的视图。 |
| 共同的历史正在悄然改写 | 编辑一份主要历史记录的多名工作人员可能会丢失或合并不兼容的决策。 | 添加新的源历史记录而不覆盖以前的条目。从该历史记录构建当前视图，而无需重写事件记录。 |
| 不同时期、不同州一视同仁 | 当前的、历史的、实验的、单独测试的和替换的陈述都被呈现，就好像它们具有相同的地位一样。 | 存储每个重要索赔和系统部件的时间和当前状况。 |
| 删除一个部件而不检查谁使用它 | 当前流程中未使用的部分被视为过时，而不检查依赖于它的后续工作。 | 记录每个部件的工作、用户、当前状态和替换情况。在删除之前检查这些用户。 |
| 将生成的文本混合到个人记录中 | 语言模型编写的解释以一种后来可能被误认为是人自己的话语或信仰的形式保存在人类材料旁边。 | 将逐字的人类材料、抄本和语言模型生成的解释清楚地分开。永远不要让生成的文本默默地成为人类记录的一部分。 |
| 在清理期间删除历史记录 | 早期的记录被更改或删除，因为语言模型判断它们不正确或不整洁。这破坏了理解发生了什么以及为什么发生变化所需的证据。 | 保存历史记录。添加更正或稍后的发现，而不是默默地重写过去。 |

## 指令和范围失败

| 观察到的故障 | 发生了什么 | 在语言模型之外添加的保护 |
|---|---|---|
| 任务期间规则丢失 | 语言模型可以读取、重述，然后​​违反同一任务中的规则。 | 将失败成本较高的规则转变为可以拒绝工作的所需条件和检查。 |
| 在没有证据的情况下遵循索赔规则 | 当结果显示并非如此时，该模型声称已遵循指示或文件。 | 需要相关检查已运行并通过的证据。语言模型说它成功并不能证明。 |
| 替换请求的任务 | 特定的请求被语言模型的首选框架所取代，迫使用户再次争论原始作品。 | 保留所要求的限制。拒绝未经请求的框架更改，除非真正的安全或权限冲突需要这样做。 |
| 未经许可进行额外工作 | 进行了相关工作，因为它看起来很有用，尽管没有提出要求。 | 将每一个行动与所宣布的任务联系起来。将任何扩张视为新的决定。 |
| 更改请求的目的地 | 当请求的位置无法访问时，结果会被移动到更容易的地方，而不是修复访问。 | 保留所选目的地。改变它需要用户的决定。 |
| 超越所要求的更正 | 反馈被视为不断改变工作的方向，而不是达到的精确修正。 | 记录所请求的最终状态并在更改后检查结果。 |
| 将新材料强行放到错误的地方 | 新材料被添加到现有文档中，但没有将其融入到结构中，这会损坏两者。 | 规划完整的结果，跟踪添加的更改，并在不属于的情况下创建单独的文档。 |
| 移动输出而不是固定访问 | 当无法访问所请求的文件夹时，助手会将结果移动到更容易的地方。这会分割该人的记录，并丢弃围绕原始位置已经建立的归档、权限和习惯。 | 修复对所选位置的访问。改变目的地仍然是个人的决定。 |

## 证据和完成失败

| 观察到的故障 | 发生了什么 | 在语言模型之外添加的保护 |
|---|---|---|
| 宣布完成为时过早 | 在测试其效果之前，编辑或开始一个部分被报告为完成。 | 完成需要提供所请求结果的证据，而不是生成的状态声明。 |
| 未经检查就接受诊断 | 错误消息被接受，但没有检查它来自何处、何时或是否描述了当前任务。 | 将证据与证据的产生地点、时间和情况联系起来。 |
| 合理的猜测 | 提出原因和后续步骤是因为它们听起来合理，而不是因为证据表明它们。 | 保留未知数。将观察到的内容、可能的解释、测试和已确认的原因分开。 |
| 假设最新的更改是正确的 | 最近的语言模型编写的更改被认为是正确的，而其他部分首先被怀疑。 | 在分配原因之前检查最新的更改和竞争的解释。 |
| 将时间视为原因的证据 | 在没有比较正常行为或其他变化条件的情况下，将故障归咎于接近故障的部分。 | 让问题再次发生。比较正常情况和变化的情况，寻找相反的证据，并追踪原因。 |
| 将小测试视为实时行为的证据 | 提出了模仿、准备好的示例或小型测试，以证明整个系统在正常使用中工作正常。 | 准确说明测试的内容，不要声称结果证明了更多。 |
| 使用错误的权限进行测试 | 即使实时程序以不同的权限运行，也可以使用开发人员的访问权限进行检查。 | 使用实时程序使用的相同帐户和权限进行测试，或者保留结果未经验证。 |
| 录制前修复错误 | 一个错误在被披露之前就被修复了，使记录看起来比作品更干净。 | 按顺序保留失败和纠正。不要让修复抹掉证据。 |
| 在用户面前反复修改 | 结果在用户面前反复修改，因为计划被推迟到第一个结果之后。 | 在要求审查之前选择材料并计划整个结果。尽可能提交一份有限的草稿。 |
| 因编辑不完整而中断实时服务 | 语言模型仅更改了工作文件的一部分并继续前进。正在运行的服务无法完成其工作。 | 将更改视为未完成，直到整个文件有效并且实际服务完成预期作业。 |
| 更改错误的设置副本 | 语言模型编辑了主设置文件，重新启动服务，收到成功的重新启动响应，并报告成功。该服务使用不同的生成副本，因此旧设置保持活动状态。 | 验证可见结果，而不仅仅是编辑或重新启动消息。从主要设置到服务实际使用的副本保持一条清晰的路径。 |
| 多次修复仍无法解决问题 | 针对一个问题做了四处修改。每一个都证明了一些代码运行了，但没有一个证明原来的问题已经消失。 | 定义编辑前必须更改的结果。每次更改后，直接测试结果。 |
| 检查实时服务没有的访问权限 | 通过该人的帐户进行测试时，文件夹可以工作，但实时服务使用不同的帐户，仍然无法访问它。 | 在与实时服务相同的条件下运行检查。 |

## 不知道谁可以说什么或批准什么

| 观察到的故障 | 发生了什么 | 在语言模型之外添加的保护 |
|---|---|---|
| 不同的工作被视为相同 | 观察员、作家、检查员、可以停止工作的人以及发布批准者都被视为相同的，因为每个人都触及了结果。 | 每个部分都有其规定的工作以及它可以做出的决定的限制。作家无法使某个主张成立。观察者无法发布。 |
| 将替代值显示为真实值 | 屏幕显示空的测量值或看似合理的替代品，因此安装看起来已经完成。 | 显示测量值及其来源，或明确说明该值不可用。 |
| 刷新页面破坏了用户的位置 | 刷新替换了整个页面并破坏了焦点、选择、滚动位置或复制。 | 将屏幕视为人类工作空间。更新变化的值而不破坏用户的位置。 |
| 将密码保存在不受保护的文本中 | 密码和访问密钥被放置在普通文件中，而不是受保护的存储中。 | 将它们保存在受保护的存储中，并在发布前检查每个文件。 |
| 报告服务在继续运行时停止 | 停止请求成功返回，但进程继续工作。 | 检查控制请求后的流程及其实际效果。请勿将请求报告为结果。 |

## 人类注意力失败

| 观察到的故障 | 发生了什么 | 在语言模型之外添加的保护 |
|---|---|---|
| 填充一个人的话 | 简短的人类陈述用生成的材料进行扩展，直到很难找到原始单词。 | 保留原始报表作为主要记录。生成的解释仍然是独立且可选的。 |
| 循环书写 | 在有用的内容用完之后，对答案进行了解释、重述、重述和总结。 | 当请求的结果完成时停止。删除重复的结论。 |
| 埋葬答案 | 一两个有用的事实被放置在用户没有请求的整屏材料中。 | 首先放置最短的完整答案，并选择更深层次的材料。 |
| 花费不被关注的注意力 | 正确但不必要的解释迫使读者花时间决定这是不必要的。 | 将阅读和更正视为实际成本。让读者发起可选的深度。 |
| 过分强调 | 几乎每个点都是粗体、有标题或放在表格中，因此真正的警告不再引人注目。 | 仅强调少数具有决策或安全负担的区别。 |

## 涉及成本和供应商激励的失败

| 观察到的故障 | 发生了什么 | 在语言模型之外添加的保护 |
|---|---|---|
| 默认使用的付费大语言模型 | 工作是通过付费在线模型发送的，因为它是可用的，即使简单的固定流程、保存的结果或有限的工具可以更可靠地完成它。 | 衡量工作的全部价值和成本。选择其工作可被检查和证明的最小工具组合。 |
| 修正成本从总计中消失 | 在出现不好的结果后，重试、重复上下文、等待和人工纠正都被视为免费，尽管它们使用了付费津贴并需要人投入更多的时间和精力。 | 将等待、重试、拒绝、重复服务使用和人工关注记录为实际成本的一部分。 |
| 失败的工作不会返回配额 | 不可用的输出和纠正它所需的交换计入付费配额。该人不会自动获得补偿损失的津贴或时间。 | 分别记录失败和纠正使用情况。重用保存的上下文和拒绝的结果，这样就不会再次购买相同的失败。 |
| 有用的失败被丢弃 | 一个被拒绝的答案消失了，所以后来的工作又犯了同样的错误，并再次付出了代价。 | 将拒绝的结果及其拒绝原因保留在公认的知识之外。重复使用该课程而不接受不受支持的声明。 |
| 必须再次提供相同的上下文 | 当早期信息从语言模型的工作视图中消失时，人们必须重建请求并重新发送付费会话中已提供的历史记录。 | 将持久上下文保留在服务之外。为每项工作建立一个有限的包，并保留退回的工作、更正和拒绝的工作以供以后使用。 |

## 这些服务失败如何成为这个项目的设计

观察到的问题并不限于弱模型。这位临时助理还被要求担任自己工作的记忆、历史学家、计划者、作家、检查者和评判者。即使是最强大的付费模型也可能在单个任务上取得成功，同时失​​去将其与其他一切联系起来的人类历史。

Robot Brain 将这些工作分配给不同的部分。源守护者保存该事件。专注的本地读者研究定义的特征。请求生成器为一个目的收集证据。模型可以提供背景或措辞。独立检查和人工批准决定接受什么。

历史记录不属于付费服务。模型可以帮助完成选定的工作，但它不会存储人的生活，也不会成为使用已完成工作的唯一方式。

本地模型也有同样的限制。它没有根据该人的记录进行训练。它读取选定的材料，返回一个过时的建议，并且可以替换。人的言语、时间、经验、决定、失败和纠正都是有价值的部分。
