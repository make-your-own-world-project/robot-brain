# ความล้มเหลวที่พบในบริการโมเดลภาษาแบบชำระเงิน-และการป้องกันที่เกิดขึ้น

![ความล้มเหลวที่บันทึกไว้กลายเป็นบททดสอบและการป้องกันสำหรับการทำงานในภายหลัง](../../illustrations/failures-became-blueprint.png)

## นี่เป็นตัวเลือกการชำระเงินที่แข็งแกร่งที่สุด

โปรเจ็กต์นี้ใช้บริการแบบจำลองภาษาออนไลน์แบบชำระเงินเพื่อการวิจัย การเขียนโค้ด การเขียน และการทบทวน บัญชีดังกล่าวรวมโมเดลทั่วไปที่แข็งแกร่งที่สุดที่ให้บริการเหล่านั้นในขณะนั้น การเลือกตัวเลือกการชำระเงินที่มีความสามารถมากกว่าไม่ได้ป้องกันความล้มเหลวด้านล่าง

แต่ละตัวอย่างมาจากบันทึกโครงการลงวันที่ ตารางจะอธิบายว่าโมเดลแบบชำระเงินทำอะไรได้บ้าง เกิดอะไรขึ้นต่อไป และการป้องกันใดที่ถูกสร้างขึ้นภายนอกโมเดล สิ่งเหล่านี้คือความล้มเหลวที่พบในบริการเชิงพาณิชย์ ไม่ใช่ความล้มเหลวที่เกิดจากRobot Brain. คอลัมน์ด้านขวาอธิบายว่าโครงการนี้ตอบสนองอย่างไร

บันทึกไม่ได้คาดเดาถึงแรงจูงใจของผู้ให้บริการหรืออ้างว่าทราบสาเหตุทางเทคนิคที่ไม่เปิดเผย ชื่อของผู้ให้บริการจะถูกละไว้เนื่องจากมาตรการป้องกันตอบสนองต่อพฤติกรรมที่เกิดขึ้นซ้ำๆ แทนที่จะเป็นบริษัทเดียว

## ความล้มเหลวมีค่าใช้จ่ายเท่าไร

ค่าใช้จ่ายไม่ได้จำกัดอยู่เพียงคำตอบที่ผิด

- **เสียเวลาไป** งานที่อธิบายไว้เมื่อเสร็จแล้วต้องได้รับการตรวจสอบ อธิบายอีกครั้ง ซ่อมแซม และทดสอบโดยบุคคลนั้น ความล้มเหลวบางอย่างใช้เวลานานหลายชั่วโมง
- **ค่าเผื่อการใช้งานที่ชำระเงิน บางครั้งเรียกว่าโควต้า สูญหายไป** การลองใหม่ บริบทซ้ำ ร่างการเปลี่ยน และการแก้ไขใช้ค่าเผื่อที่จำกัดเดียวกันกับงานที่มีประโยชน์ ในเซสชันที่บันทึกไว้เหล่านี้ จะไม่มีการส่งคืนโควต้าอัตโนมัติสำหรับเอาต์พุตที่ใช้ไม่ได้หรือการแลกเปลี่ยนแก้ไข
- **ชำระค่าบริการด้วยวิธีใดวิธีหนึ่ง** ค่าธรรมเนียมการสมัครสมาชิกหรือการใช้งานยังคงมีอยู่ในขณะที่บุคคลนั้นก็ใช้เวลาและความพยายามที่จำเป็นในการค้นหาและซ่อมแซมความล้มเหลวด้วย
- **การทำงานเสียหาย** การแก้ไขที่ไม่สมบูรณ์ทำให้บริการสดไม่สามารถทำงานได้ มีการเปลี่ยนแปลงสำเนาการตั้งค่าที่ไม่ถูกต้อง เอาท์พุตถูกย้ายออกจากตำแหน่งที่ต้องการแทนที่จะซ่อมแซมการเข้าถึง
- **บันทึกทางประวัติศาสตร์ตกอยู่ในความเสี่ยง** ข้อความที่สร้างขึ้นผสมกับเนื้อหาของมนุษย์ และบันทึกถูกเปลี่ยนแปลงหรือลบออกก่อนที่บุคคลจะอนุมัติการเปลี่ยนแปลงนั้น
- **ความสนใจถูกใช้ไปโดยไม่ได้รับอนุญาต** คำตอบที่สำคัญถูกฝังอยู่ในคำอธิบายซ้ำๆ บังคับให้บุคคลนั้นอ่านทุกอย่างเพื่อกู้คืนส่วนเล็กๆ ที่สำคัญ

นี่คือสาเหตุที่กฎสำคัญไม่ได้แสดงเฉพาะในพรอมต์ที่นี่เท่านั้นRobot Brain ตรวจสอบสิ่งที่เกิดขึ้นจริงและสามารถปฏิเสธการมีส่วนร่วมได้แม้ว่าแบบจำลองจะบอกว่าสำเร็จก็ตาม

## ความต่อเนื่องและความล้มเหลวของความรู้

| ความล้มเหลวที่สังเกตได้ | เกิดอะไรขึ้น | เพิ่มการป้องกันนอกโมเดลภาษา |
|---|---|---|
| ฟังดูต่อเนื่องหลังจากสูญเสียประวัติศาสตร์ | บริการจะย่อการสนทนาก่อนหน้านี้ให้สั้นลงเพื่อให้เหมาะสมกับขีดจำกัดการทำงาน มันเก็บข้อสรุปไว้บางส่วนแต่สูญเสียแหล่งที่มา การแก้ไข ทางเลือกอื่นที่ถูกปฏิเสธ ลำดับเหตุการณ์ และความตั้งใจของผู้ใช้ ในขณะที่ยังคงฟังดูคล่องต่อไป | เก็บบทสนทนาให้สมบูรณ์ตามลำดับ บันทึกเวอร์ชันย่อแยกต่างหาก และบันทึกสิ่งที่รวมไว้ ละเว้น และอาจสูญหายไป |
| คำตอบใหม่แทนที่ประวัติที่บันทึกไว้ | คำตอบแบบจำลองภาษาที่ใหม่กว่าอาจปรากฏขึ้นเพื่อแทนที่ทุกสิ่งก่อนหน้านั้น แม้ว่าจะมาจากข้อมูล กฎเกณฑ์ และทางเลือกที่แตกต่างกันเกี่ยวกับโลกก็ตาม | บันทึกการค้นพบแต่ละครั้งด้วยเวลาของมัน อย่าปล่อยให้คำตอบใหม่ล่าสุดมาแทนที่การค้นพบที่ได้รับการยอมรับ ปฏิเสธ หรือไม่แน่ใจก่อนหน้านี้ |
| การเรียนรู้แบบภาษาทำลายเส้นทางกลับไปยังแหล่งที่มา | โมเดลภาษาเก็บรูปแบบที่เป็นประโยชน์ไว้โดยแยกออกจากผู้สร้างแหล่งที่มา วัตถุประสงค์ ผู้ฟัง หลักฐาน ความขัดแย้ง และประวัติศาสตร์ในภายหลัง | เก็บแหล่งข้อมูลที่ไม่เปลี่ยนแปลงและการเชื่อมต่อที่รู้จักไว้นอกโมเดลทุกภาษา ถือว่าความรู้แบบจำลองภาษาที่ไม่ได้รับการสนับสนุนเป็นข้อเสนอแนะ เว้นแต่หลักฐานที่แยกจากกันจะเชื่อมโยงความรู้นั้นกับแหล่งข้อมูลอีกครั้ง |
| สูญเสียสถานการณ์เบื้องหลังสิ่งที่โมเดลภาษาเรียนรู้มา | โมเดลภาษายังคงมีประโยชน์ในขณะที่คำตอบไม่สามารถเปิดเผยบุคคล แหล่งที่มา วัตถุประสงค์ ความขัดแย้ง การอนุญาต และวัฒนธรรมที่เป็นรูปเป็นร่างได้ทั้งหมด | เก็บสถานการณ์ที่ทราบและให้เครดิตกับแหล่งข้อมูลที่บันทึกไว้นอกโมเดลภาษา ถือว่าความรู้ที่ไม่ได้รับการสนับสนุนเป็นข้อเสนอแนะแบบจำลองภาษา ไม่ใช่ข้อเท็จจริงที่เชื่อมโยงกับแหล่งข้อมูล |
| อคติที่ซ่อนอยู่จากสิ่งที่เลือก | สิ่งที่โมเดลภาษาสามารถจดจำได้นั้นสะท้อนถึงภาษา แหล่งที่มา เอกสารสำคัญ ป้ายกำกับ ผู้ตรวจสอบที่เป็นมนุษย์ และเป้าหมายที่ใช้ในการสร้าง คำตอบไม่ได้เปิดเผยอิทธิพลเหล่านั้นทั้งหมด | บันทึกขีดจำกัดที่ทราบของโมเดลภาษา และสิ่งที่ทราบเกี่ยวกับเนื้อหาที่เรียนรู้มา เปรียบเทียบเครื่องมือที่มีจำกัดหลายๆ อย่าง และอย่าถือว่าคำตอบที่ราบรื่นเพียงคำตอบเดียวเป็นมุมมองที่สมบูรณ์ |
| ประวัติศาสตร์ที่แบ่งปันถูกเขียนใหม่อย่างเงียบๆ | คนงานหลายคนที่แก้ไขประวัติศาสตร์ที่ดูเป็นหลักอาจสูญเสียหรือรวมการตัดสินใจที่เข้ากันไม่ได้ | เพิ่มประวัติแหล่งที่มาใหม่โดยไม่ต้องเขียนทับรายการก่อนหน้า สร้างมุมมองปัจจุบันจากประวัตินั้นโดยไม่ต้องเขียนบันทึกเหตุการณ์ใหม่ |
| เวลาและรัฐที่ต่างกันถือว่าเท่าเทียมกัน | ข้อความปัจจุบัน ประวัติศาสตร์ การทดลอง ทดสอบแยกกัน และแทนที่ถูกนำเสนอราวกับว่าพวกเขามีจุดยืนเดียวกัน | เก็บเวลาและสถานะปัจจุบันพร้อมคำกล่าวอ้างและส่วนระบบที่สำคัญทั้งหมด |
| การถอดชิ้นส่วนโดยไม่ตรวจสอบว่าใครใช้ | ส่วนที่ไม่ได้ใช้ในกระบวนการปัจจุบันจะถือว่าล้าสมัยโดยไม่ต้องตรวจสอบงานในภายหลังที่ขึ้นอยู่กับชิ้นส่วนนั้น | บันทึกงานของแต่ละชิ้นส่วน ผู้ใช้ สถานะปัจจุบัน และการเปลี่ยนทดแทน ตรวจสอบผู้ใช้เหล่านั้นก่อนที่จะลบออก |
| การผสมข้อความที่สร้างขึ้นลงในบันทึกของบุคคล | คำอธิบายที่เป็นลายลักษณ์อักษรของภาษาได้รับการบันทึกไว้ข้างๆ เนื้อหาของมนุษย์ในรูปแบบที่อาจถูกเข้าใจผิดว่าเป็นคำพูดหรือความเชื่อของบุคคลนั้นในภายหลัง | แยกเนื้อหาของมนุษย์ การถอดเสียง และการตีความตามแบบจำลองภาษาออกจากกันอย่างชัดเจน อย่าปล่อยให้ข้อความที่สร้างขึ้นมาเป็นส่วนหนึ่งของบันทึกของมนุษย์อย่างเงียบๆ |
| การลบประวัติระหว่างการล้างข้อมูล | บันทึกก่อนหน้านี้มีการเปลี่ยนแปลงหรือถูกลบออกเนื่องจากแบบจำลองภาษาตัดสินว่าไม่ถูกต้องหรือไม่เป็นระเบียบ นั่นทำลายหลักฐานที่จำเป็นในการทำความเข้าใจว่าเกิดอะไรขึ้นและเหตุใดจึงเปลี่ยนแปลง | อนุรักษ์บันทึกประวัติศาสตร์ เพิ่มการแก้ไขหรือค้นหาในภายหลัง แทนที่จะเขียนอดีตซ้ำอย่างเงียบๆ |

## ความล้มเหลวของคำสั่งและขอบเขต

| ความล้มเหลวที่สังเกตได้ | เกิดอะไรขึ้น | เพิ่มการป้องกันนอกโมเดลภาษา |
|---|---|---|
| กฎที่สูญหายระหว่างภารกิจ | โมเดลภาษาสามารถอ่าน ย้ำ และละเมิดกฎในงานเดียวกันได้ | เปลี่ยนกฎที่ความล้มเหลวมีค่าใช้จ่ายสูงให้เป็นเงื่อนไขที่จำเป็น และตรวจสอบที่สามารถปฏิเสธงานได้ |
| มีการปฏิบัติตามกฎการอ้างสิทธิ์โดยไม่มีหลักฐาน | แบบจำลองอ้างว่าได้ปฏิบัติตามคำแนะนำหรือเอกสารเมื่อผลลัพธ์แสดงเป็นอย่างอื่น | ต้องมีหลักฐานว่าเช็คที่เกี่ยวข้องวิ่งแล้วผ่าน แบบจำลองภาษาที่บอกว่าประสบความสำเร็จนั้นไม่ใช่ข้อพิสูจน์ |
| แทนที่งานที่ร้องขอ | คำขอเฉพาะถูกแทนที่ด้วยเฟรมที่ต้องการของโมเดลภาษา ทำให้ผู้ใช้ต้องโต้แย้งสำหรับงานต้นฉบับอีกครั้ง | รักษาขีดจำกัดที่ร้องขอ ปฏิเสธการเปลี่ยนแปลงเฟรมที่ไม่มีการร้องขอ เว้นแต่ว่าจำเป็นต้องมีข้อขัดแย้งด้านความปลอดภัยหรือการอนุญาต |
| การทำงานพิเศษโดยไม่ได้รับอนุญาต | งานที่เกี่ยวข้องได้รับการดำเนินการเนื่องจากดูมีประโยชน์ แม้ว่าจะไม่มีการร้องขอก็ตาม | ผูกทุกการกระทำเข้ากับงานที่ประกาศ ถือว่าการขยายใด ๆ เป็นเหมือนการตัดสินใจครั้งใหม่ |
| การเปลี่ยนปลายทางที่ร้องขอ | เมื่อไม่สามารถเข้าถึงตำแหน่งที่ร้องขอได้ ผลลัพธ์จะถูกย้ายไปที่อื่นที่ง่ายกว่าแทนที่จะซ่อมแซมการเข้าถึง | รักษาจุดหมายปลายทางที่เลือกไว้ การเปลี่ยนแปลงต้องอาศัยการตัดสินใจของผู้ใช้ |
| ก้าวข้ามการแก้ไขที่ร้องขอ | ผลตอบรับถือเป็นแนวทางในการเปลี่ยนแปลงงานอย่างต่อเนื่องแทนที่จะแก้ไขอย่างแม่นยำเพื่อให้บรรลุผล | บันทึกสถานะสุดท้ายที่ร้องขอ และตรวจสอบผลลัพธ์หลังการเปลี่ยนแปลง |
| การบังคับวัสดุใหม่เข้าที่ผิด | มีการเพิ่มวัสดุใหม่ลงในเอกสารที่มีอยู่โดยไม่ได้ติดตั้งเข้ากับโครงสร้าง ซึ่งทำให้ทั้งสองอย่างเสียหาย | วางแผนผลลัพธ์ที่สมบูรณ์ ติดตามการเปลี่ยนแปลงเพิ่มเติม และสร้างเอกสารแยกต่างหากเมื่อไม่ได้เป็นส่วนหนึ่งของเอกสาร |
| การย้ายเอาต์พุตแทนที่จะแก้ไขการเข้าถึง | เมื่อไม่สามารถเข้าถึงโฟลเดอร์ที่ร้องขอได้ ผู้ช่วยจะย้ายผลลัพธ์ไปที่อื่นได้ง่ายขึ้น ซึ่งแยกบันทึกของบุคคลนั้นและละทิ้งการยื่นเรื่อง การอนุญาต และนิสัยที่สร้างไว้แล้วในบริเวณเดิม | ซ่อมแซมการเข้าถึงตำแหน่งที่เลือก การเปลี่ยนจุดหมายปลายทางยังคงเป็นการตัดสินใจของบุคคลนั้น |

## หลักฐานและความล้มเหลวในการดำเนินการให้เสร็จสิ้น

| ความล้มเหลวที่สังเกตได้ | เกิดอะไรขึ้น | เพิ่มการป้องกันนอกโมเดลภาษา |
|---|---|---|
| ประกาศเสร็จเร็วเกินไป | การแก้ไขหรือเริ่มส่วนหนึ่งได้รับการรายงานว่าเสร็จสิ้นก่อนที่จะมีการทดสอบผลกระทบ | การดำเนินการให้เสร็จสิ้นจำเป็นต้องมีหลักฐานสำหรับผลลัพธ์ที่ร้องขอ ไม่ใช่คำชี้แจงสถานะที่สร้างขึ้น |
| ยอมรับการวินิจฉัยโดยไม่ตรวจสอบ | ยอมรับข้อความแสดงข้อผิดพลาดโดยไม่ตรวจสอบว่าข้อความดังกล่าวมาจากไหนและเมื่อใด หรืออธิบายงานปัจจุบันหรือไม่ | เก็บหลักฐานโดยเชื่อมโยงกับสถานที่ เมื่อใด และภายใต้สถานการณ์ใด |
| การคาดเดาที่เป็นไปได้ | สาเหตุและขั้นตอนต่อไปถูกเสนอเพราะฟังดูสมเหตุสมผล ไม่ใช่เพราะหลักฐานชี้ให้เห็น | อนุรักษ์สิ่งที่ไม่รู้จัก แยกสิ่งที่สังเกตได้ คำอธิบายที่เป็นไปได้ การทดสอบ และสาเหตุที่ยืนยันได้ |
| สมมติว่าการเปลี่ยนแปลงล่าสุดถูกต้อง | การเปลี่ยนแปลงที่เขียนด้วยแบบจำลองภาษาล่าสุดถือว่าถูกต้องในขณะที่ส่วนอื่นๆ ถูกสงสัยก่อน | ตรวจสอบการเปลี่ยนแปลงล่าสุดและคำอธิบายที่แข่งขันกันก่อนกำหนดสาเหตุ |
| การรักษาเวลาเป็นข้อพิสูจน์ถึงสาเหตุ | ชิ้นส่วนที่ทำงานใกล้เกิดความล้มเหลวถูกตำหนิโดยไม่ต้องเปรียบเทียบพฤติกรรมปกติหรือสภาวะที่เปลี่ยนแปลงอื่นๆ | ให้ปัญหาเกิดขึ้นอีก เปรียบเทียบสภาวะปกติและสภาวะที่เปลี่ยนแปลง มองหาหลักฐานที่ขัดแย้งกัน และติดตามสาเหตุ |
| ถือว่าการทดสอบเล็กๆ น้อยๆ เป็นการพิสูจน์พฤติกรรมที่เกิดขึ้นจริง | มีการนำเสนอการเลียนแบบ ตัวอย่างที่เตรียมไว้ หรือการทดสอบเล็กๆ น้อยๆ เพื่อเป็นข้อพิสูจน์ว่าทั้งระบบทำงานได้ตามปกติ | ระบุสิ่งที่ได้รับการทดสอบอย่างชัดเจนและอย่าอ้างว่าผลลัพธ์พิสูจน์ได้มากกว่านี้ |
| การทดสอบด้วยการอนุญาตที่ไม่ถูกต้อง | การตรวจสอบผ่านการใช้การเข้าถึงของนักพัฒนาแม้ว่าโปรแกรมถ่ายทอดสดจะทำงานด้วยสิทธิ์ที่แตกต่างกันก็ตาม | ทดสอบด้วยบัญชีเดียวกันและการอนุญาตที่ใช้โดยโปรแกรมถ่ายทอดสด หรือปล่อยให้ผลลัพธ์ไม่ได้รับการพิสูจน์ |
| การแก้ไขข้อผิดพลาดก่อนที่จะบันทึก | ข้อผิดพลาดได้รับการซ่อมแซมก่อนที่จะเปิดเผย ทำให้บันทึกดูสะอาดตากว่างานที่ทำ | รักษาความผิดพลาดและการแก้ไขตามลำดับ อย่าให้การซ่อมแซมลบหลักฐาน |
| แก้ไขซ้ำต่อหน้าผู้ใช้ | ผลลัพธ์ได้รับการแก้ไขซ้ำๆ ต่อหน้าผู้ใช้ เนื่องจากการวางแผนล่าช้าจนกระทั่งหลังจากผลลัพธ์แรก | เลือกวัสดุและวางแผนผลลัพธ์ทั้งหมดก่อนที่จะขอให้ตรวจสอบ นำเสนอฉบับร่างแบบจำกัดหนึ่งฉบับเมื่อเป็นไปได้ |
| ทำลายบริการสดด้วยการแก้ไขที่ไม่สมบูรณ์ | โมเดลภาษาเปลี่ยนเพียงส่วนหนึ่งของไฟล์การทำงานและเดินหน้าต่อไป บริการที่กำลังทำงานอยู่ไม่สามารถทำงานให้เสร็จสิ้นได้ | ถือว่าการเปลี่ยนแปลงยังไม่เสร็จสิ้นจนกว่าไฟล์ทั้งหมดจะใช้งานได้และบริการจริงจะทำงานตามที่ต้องการให้เสร็จสิ้น |
| การเปลี่ยนสำเนาการตั้งค่าที่ไม่ถูกต้อง | โมเดลภาษาแก้ไขไฟล์การตั้งค่าหลัก เริ่มบริการใหม่ ได้รับการตอบกลับการรีสตาร์ทสำเร็จ และรายงานความสำเร็จ บริการใช้สำเนาที่สร้างขึ้นที่แตกต่างกัน ดังนั้นการตั้งค่าเก่าจึงยังคงทำงานอยู่ | ตรวจสอบผลลัพธ์ที่มองเห็นได้ ไม่ใช่แค่ข้อความแก้ไขหรือรีสตาร์ท เก็บเส้นทางที่ชัดเจนเพียงเส้นทางเดียวจากการตั้งค่าหลักไปยังสำเนาที่บริการใช้จริง |
| การแก้ไขซ้ำแล้วซ้ำอีกซึ่งไม่ได้แก้ไขปัญหา | มีการเปลี่ยนแปลงสี่ครั้งสำหรับปัญหาเดียว แต่ละข้อพิสูจน์ว่าโค้ดบางตัวทำงาน แต่ไม่มีใครพิสูจน์ได้ว่าปัญหาเดิมหมดไป | กำหนดผลลัพธ์ที่ต้องเปลี่ยนแปลงก่อนทำการแก้ไข หลังจากการเปลี่ยนแปลงแต่ละครั้ง ให้ทดสอบผลลัพธ์นั้นโดยตรง |
| ไม่มีการตรวจสอบการเข้าถึงบริการสด | โฟลเดอร์ใช้งานได้เมื่อทดสอบผ่านบัญชีของบุคคลนั้น แต่บริการที่ใช้งานจริงใช้บัญชีอื่นและยังคงไม่สามารถเข้าถึงได้ | ดำเนินการตรวจสอบภายใต้เงื่อนไขเดียวกันกับบริการที่ใช้งานจริง |

## ความล้มเหลวเกี่ยวกับใครจะพูดหรืออนุมัติอะไร

| ความล้มเหลวที่สังเกตได้ | เกิดอะไรขึ้น | เพิ่มการป้องกันนอกโมเดลภาษา |
|---|---|---|
| งานที่แตกต่างกันได้รับการปฏิบัติเหมือนกัน | ผู้สังเกตการณ์ นักเขียน ผู้ตรวจสอบ ผู้ที่สามารถหยุดงาน และผู้อนุมัติการปล่อยตัวได้รับการปฏิบัติแบบเดียวกันเพราะแต่ละคนสัมผัสผลลัพธ์กัน | ทุกส่วนมีงานที่ระบุไว้และมีข้อจำกัดในสิ่งที่อาจตัดสินใจได้ ผู้เขียนไม่สามารถกล่าวอ้างได้ว่าเป็นความจริง ผู้สังเกตการณ์ไม่สามารถเผยแพร่ได้ |
| การแสดงค่าทดแทนตามความเป็นจริง | หน้าจอแสดงการวัดที่ว่างเปล่าหรือสิ่งทดแทนที่เป็นไปได้ ดังนั้นการติดตั้งจึงดูเสร็จสมบูรณ์ | แสดงค่าที่วัดได้และแหล่งที่มา หรือระบุให้ชัดเจนว่าไม่มีให้บริการ |
| การรีเฟรชเพจทำลายสถานที่ของผู้ใช้ | การรีเฟรชแทนที่ทั้งหน้าและทำลายโฟกัส การเลือก ตำแหน่งการเลื่อน หรือการคัดลอก | ปฏิบัติต่อหน้าจอเสมือนเป็นพื้นที่ทำงานของมนุษย์ อัพเดตค่าที่เปลี่ยนแปลงโดยไม่ทำลายตำแหน่งของผู้ใช้งาน |
| เก็บรหัสผ่านเป็นข้อความที่ไม่มีการป้องกัน | รหัสผ่านและคีย์การเข้าถึงถูกวางไว้ในไฟล์ธรรมดาแทนที่จะเป็นที่เก็บข้อมูลที่มีการป้องกัน | เก็บไว้ในที่เก็บข้อมูลที่มีการป้องกันและตรวจสอบทุกไฟล์ก่อนเผยแพร่ |
| การรายงานว่าบริการหยุดทำงานในขณะที่ยังคงทำงานอยู่ | คำขอหยุดส่งคืนสำเร็จ แต่กระบวนการยังคงทำงานต่อไป | ตรวจสอบกระบวนการและผลกระทบที่แท้จริงหลังจากการร้องขอการควบคุม อย่ารายงานคำขอเป็นผล |

| โมเดลภาษาขนาดใหญ่ที่ต้องชำระเงินใช้เป็นค่าเริ่มต้น | งานถูกส่งผ่านโมเดลออนไลน์แบบชำระเงินเนื่องจากมีให้ใช้งาน แม้ว่ากระบวนการแก้ไขง่ายๆ ผลลัพธ์ที่บันทึกไว้ หรือเครื่องมือที่มีจำกัดจะสามารถทำงานได้อย่างน่าเชื่อถือมากขึ้นก็ตาม | วัดมูลค่าเต็มและต้นทุนของงาน เลือกชุดเครื่องมือที่เล็กที่สุดที่สามารถตรวจสอบและจัดวางได้ |
| ค่าแก้ไขหายไปจากยอดรวม | การลองใหม่ บริบทที่ทำซ้ำ การรอ และการแก้ไขโดยเจ้าหน้าที่จะถือว่าไม่มีค่าใช้จ่ายหลังจากผลลัพธ์ที่ไม่ดี แม้ว่าพวกเขาจะใช้เบี้ยเลี้ยงที่จ่ายไปแล้วและเรียกร้องเวลาและพลังงานของบุคคลนั้นมากขึ้นก็ตาม | บันทึกการรอ การลองใหม่ การปฏิเสธ การใช้บริการซ้ำ และความสนใจของมนุษย์ ซึ่งเป็นส่วนหนึ่งของต้นทุนที่แท้จริง |
| ไม่มีการคืนโควต้าสำหรับงานที่ล้มเหลว | เอาต์พุตที่ใช้งานไม่ได้และการแลกเปลี่ยนที่จำเป็นในการแก้ไขจะนับรวมกับโควต้าที่ชำระเงิน บุคคลนั้นไม่ได้รับการทดแทนโดยอัตโนมัติสำหรับค่าเผื่อหรือเวลาที่สูญเสียไป | บันทึกล้มเหลวและใช้งานแก้ไขแยกกัน ใช้บริบทที่บันทึกไว้ซ้ำและผลลัพธ์ที่ถูกปฏิเสธ เพื่อไม่ให้ซื้อความล้มเหลวเดิมอีก |
| ความล้มเหลวที่เป็นประโยชน์ถูกยกเลิก | คำตอบที่ถูกปฏิเสธหายไป ดังนั้นงานต่อมาจึงทำผิดซ้ำแล้วซ้ำอีกและชดใช้อีกครั้ง | เก็บผลลัพธ์ที่ถูกปฏิเสธและเหตุผลในการปฏิเสธไว้นอกเหนือความรู้ที่ยอมรับ ใช้บทเรียนซ้ำโดยไม่ยอมรับการอ้างสิทธิ์ที่ไม่ได้รับการสนับสนุน |
| ต้องระบุบริบทเดียวกันอีกครั้ง | เมื่อข้อมูลก่อนหน้านี้หายไปจากมุมมองการทำงานของโมเดลภาษา บุคคลนั้นจะต้องสร้างคำขอขึ้นใหม่ และส่งประวัติที่ให้ไว้แล้วในเซสชันแบบชำระเงินอีกครั้ง | รักษาบริบทที่ยั่งยืนไว้นอกบริการ สร้างแพ็คเกจที่จำกัดสำหรับแต่ละงานและเก็บงานที่ส่งคืน การแก้ไข และการปฏิเสธเพื่อใช้ในภายหลัง |

## ความล้มเหลวในการบริการเหล่านั้นกลายเป็นการออกแบบของโครงการนี้อย่างไร

ปัญหาที่สังเกตไม่ได้จำกัดอยู่เพียงโมเดลที่อ่อนแอเท่านั้น ผู้ช่วยชั่วคราวคนเดียวกันนี้ถูกขอให้ทำหน้าที่เป็นผู้จดจำ นักประวัติศาสตร์ นักวางแผน นักเขียน ผู้ตรวจสอบ และผู้ตัดสินผลงานของตนเอง แม้แต่โมเดลที่ได้รับค่าตอบแทนที่แข็งแกร่งที่สุดก็สามารถประสบความสำเร็จในแต่ละงานได้ ในขณะเดียวกันก็สูญเสียประวัติศาสตร์ของมนุษย์ที่เชื่อมโยงกับทุกสิ่งทุกอย่างไป

Robot Brain ให้งานเหล่านั้นแยกส่วน ผู้รักษาแหล่งที่มาจะเก็บรักษาเหตุการณ์ไว้ ผู้อ่านในพื้นที่ที่มุ่งเน้นจะตรวจสอบคุณสมบัติที่กำหนดไว้ ตัวสร้างคำขอรวบรวมหลักฐานเพื่อจุดประสงค์เดียว แบบจำลองอาจสนับสนุนพื้นหลังหรือถ้อยคำ การตรวจสอบที่เป็นอิสระและการอนุมัติจากมนุษย์จะตัดสินว่าสิ่งใดเป็นที่ยอมรับ

ประวัติยังคงอยู่นอกบริการแบบชำระเงิน แบบจำลองสามารถช่วยในงานที่เลือกได้ แต่ไม่ได้เก็บชีวิตของบุคคลนั้นหรือกลายเป็นวิธีเดียวที่จะใช้งานที่ได้ทำไปแล้ว

โมเดลในเครื่องมีขีดจำกัดเดียวกัน ไม่ได้รับการฝึกอบรมเกี่ยวกับบันทึกของบุคคลนั้น โดยจะอ่านเนื้อหาที่เลือก ส่งกลับคำแนะนำที่ลงวันที่ และสามารถเปลี่ยนได้ คำพูด เวลา ประสบการณ์ การตัดสินใจ ความล้มเหลว และการแก้ไขของบุคคลนั้นถือเป็นส่วนที่มีคุณค่า
