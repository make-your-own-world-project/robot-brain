# Explicar la misma verdad a diferentes lectores.

![El mismo significado sustentado puede explicarse en formas adaptadas a diferentes lectores.](../../illustrations/human-protocol-weave.png)

Una declaración puede ser precisa y aun así resultar inútil para la persona que la lee. La respuesta puede llegar demasiado tarde, utilizar un lenguaje desconocido o esconder un hecho útil bajo páginas de explicación.

Este trabajo separa dos decisiones:

1. ¿Qué respalda la evidencia?
2. ¿Cuál es la forma más clara de explicárselo a este lector?

Cambiar la explicación no debe cambiar la evidencia.

## Pregunta en lugar de adivinar

Para un intercambio particular, el lector puede elegir una respuesta breve, una explicación detallada, texto, audio u otra forma disponible. Pueden pedir más detalles, corregir un malentendido o detenerse.

Esa elección se aplica al intercambio. No es un permiso para construir un perfil de personalidad permanente o adivinar el estado mental privado de alguien.

## La presentación no es la verdad.

Una vez que las afirmaciones respaldadas sean claras, el escrito puede cambiar el orden, los ejemplos, el nivel de detalle y la explicación de términos desconocidos.

No puede convertir una posible interpretación en un hecho. No puede eliminar una falla que el lector necesita para comprender el resultado. No puede añadir confianza sólo por parecer útil.

## El tiempo de lectura es un coste real.

Los asistentes pagados utilizados durante el desarrollo a menudo produjeron mucho más texto del solicitado. Repitieron puntos, ampliaron declaraciones breves y enfatizaron casi todo. Luego, la persona tenía que buscar la respuesta, corregirla y explicar la solicitud nuevamente.

Ese tiempo importa tanto como las tarifas de servicio y el tiempo de computación. Más palabras no son más útiles cuando hacen que la respuesta sea más difícil de encontrar.

Una buena respuesta conduce a un resultado útil. Da la explicación necesaria para comprender y utilizar ese resultado. La profundidad adicional permanece disponible cuando el lector la solicita.

## Lo que aún necesita ser probado

El software actual puede establecer requisitos de longitud, evidencia y forma terminada. Las pruebas futuras deben comparar qué tan bien sobrevive el mismo significado respaldado en diferentes lectores, idiomas, culturas y necesidades de accesibilidad.

Las personas que reciben una explicación deben poder corregirla. Su corrección pasa a formar parte del registro y no a una preferencia oculta adivinada por un modelo.
